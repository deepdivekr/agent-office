# Agent Office v0.8.18

- **Node.js 22.23.4.** Agent Office now pins Node.js 22.23.4, the [October 21, 2026 security release](https://nodejs.org/en/blog/vulnerability/october-2026-security-releases). It fixes four high-severity issues in the runtime that every outgoing HTTPS request and download goes through: TLS hostname checks that could be bypassed with fullwidth or loosely resolving IP hosts, a Brotli decoder out-of-bounds write, and `dns.resolve` truncating names at a NUL character. The bundled Undici, OpenSSL, c-ares, SQLite and CA certificates are updated too.
  - The installer downloads 22.23.4 from nodejs.org and checks its SHA-256 as before; a system Node.js of another version is not used.
  - Office's own code uses none of the affected APIs directly (no disabled certificate checks, custom hostname checks, `dns.resolve`, Brotli decoding, Permission Model or startup snapshots), so only the runtime changes.
- **hono 4.13.13.** The MCP SDK's HTTP dependency moves past [GHSA-5r4p-p66f-jhc7](https://github.com/advisories/GHSA-5r4p-p66f-jhc7) (moderate, `serveStatic` decoding a path twice). Office does not serve files through hono, so this only clears the audit.
- **The installer updates its own command after a Node.js change.** The `agent-office` command it writes names the Node.js it runs on, so an earlier install's command no longer matched and the update stopped with "Will not overwrite another agent-office command". A command that runs this install's CLI with another Node.js path is now updated; any other file there is still left alone.
- The isolated file-check preflight compares the sandbox Node.js with the running one instead of a fixed version.

## Upgrade

Finish active work, close MCP clients and the Control Center, and rerun the installer:

```bash
bash -o pipefail -c 'curl -fsSL https://raw.githubusercontent.com/deepdivekr/agent-office/v0.8.18/install.sh | bash'
```

Saved Works, schedules and settings carry over. The install verifier upgrades from v0.3.1 through v0.8.17.
