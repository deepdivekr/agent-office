# Agent Office v0.5.0

## Your own AI app runs each Work

- A Work runs on the AI app chosen at intake, Codex (`exec --json`) or Claude Code (`-p`). It uses your own settings, skills, plugins and MCP servers, in a Work folder Office owns. One app stays with a Work for its whole life; there is no handoff between apps.
- The app reports each completion condition as met (`COMPLETION.json`). A send or submission the request asked for, done by the app's own tools, also counts. Office independently verifies only what Office itself sends.
- A direction you give goes to the same app session as written; Office does not replan it. A recurring Work resumes the previous run's session.
- The Work detail shows what a run was asked to fix after a failed check, and keeps a stopped run's failure text.
- Claude failures are classified from their error fields only. Short-lived errors are retried before the Work stops.
- When your browser is unavailable, a run falls back to another permitted browser. An incomplete report is repaired before Office checks it.
- API mode and per-role model choices are retired from the Work defaults. API keys remain for Jev only.

## See and steer your Works

- **Home** is the first screen. It shows one same-size cell per Work, in a stable place:
  - its state now;
  - its latest output: the delivered text, up to four result images, or a conversation's last reply;
  - the last three lines of its log.
- The Works of one server share a cell. Summaries come from stored records; no model rewrites them.
- **Board** has five columns: Needs you · Running · Recurring · On hold · Ended.
  - Each card shows its cycle stages and who handled the Work (code, Jev, AI, you).
  - A list and a 24-hour timeline are also available.
- **Work detail** shows three panes side by side:
  - the conversation with the Work's app, where you can send the next direction;
  - a work list of what each cycle produced;
  - a log without tool noise.
- **Hide** takes a Work off the screens, for example before a screen recording. The Work keeps running, and the sidebar's Hidden view shows it.
- The sidebar shows which AI apps are connected to Office.
- Dark by default.
- An app icon for adding Office to a phone home screen.

## Bring work in

- **Import by address:** enter a folder, `owner/repo` or `user@host`. Your own AI app analyses it read-only and proposes Works to attach.
- **Server services:**
  - Office reads a Linux server's systemd services, timers and containers over one fixed read-only SSH script, and groups them into Works.
  - It sends a notice when a group's state changes.
  - Activity checks count matching journal lines within a time window.
  - Office never starts, stops or restarts anything on the server.
- **AI conversations:** attach a Claude Code or Codex session you started on the desktop as a Work. You read it, and you can continue it from Office while it is idle.

## Delivery

- The message you receive is the app's `DELIVERY.md`, not the verification record.
- Telegram carries the result pictures. A file saved without a media type is recognised as an image by its name.
- A destination added after a verified result still receives that result.

## Access

- Short address `http://office.localhost:4600/`. The capability moves into a host-only cookie.
- **Tailscale:** list your machine's MagicDNS name in `observability.tailnet_hosts` and run `tailscale serve` to open Office from your other devices. The access stays inside your tailnet, and the capability token is still required. Only `*.ts.net` names are accepted. See [Control Center](../control-center.md).

## Updating

Finish or pause active work, and stop connected MCP clients and the Control Center, before updating. Run the versioned installer, then reconnect clients. Existing data is preserved; personal credentials and workflows are not bundled.

Ubuntu 24.04 x86_64 and Windows 11 with WSL2 are the supported runtime environments. Native Windows desktop control remains experimental, and macOS is not certified by this release.

Publication requires the full quick regression suite, fresh and upgrade installation checks (now including v0.4.0) and public-boundary checks. Fixture tests are not presented as proof of live website or messenger success. [Release verification](../release-readiness-v0.5.0.md)
