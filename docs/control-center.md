# Agent Driver Control Center

Control Center는 Agent Driver가 맡은 업무의 진행 상태와 연결 설정을 보여주는 로컬 화면이다. 기본 화면은 **한 줄 업무 접수 → 업무함 → 업무 상세**이다. Browser/VNC 화면 wall과 실시간 미리보기는 없다.

```bash
agent-driver dashboard --config /absolute/path/to/host.json
```

서버는 `127.0.0.1`에만 열리고 기본 포트는 4600이다(쓰고 있으면 빈 포트로 넘어간다). capability URL이 열쇠이며, `agent-office connect`가 여는 `office.localhost` 주소에서는 그 열쇠가 host 전용 쿠키로 옮겨져 주소창에는 `http://office.localhost:4600/`만 남는다. `127.0.0.1`·`localhost`에서는 capability 경로 그대로 쓴다. 온보딩·AI 연결·Jev·사이트 로그인 설정도 이 화면에서 처리한다. 사이트 로그인은 작업에 필요할 때만 표시된다.

## 확인할 수 있는 것

- 업무(Work), 실행(Run), 단계(Step)와 실제 저장된 계획·담당·활동·근거·결과
- 한 줄 업무의 영속 접수, 기본/심화 정의, 선택지 답변과 업무 조건 버전
- 단계별 진행 상태, 멈춘 이유, 누가 이어받았는지
- 최근 MCP heartbeat와 Browser/VM·CLI·Decision Plane 연결 상태
- 사람이 허용된 단계에 지침을 수정하거나 읽기 전용 Swarm 실행을 일시정지·재개하는 동작

화면은 Agent Driver에 보고된 작업만 표시한다. 다른 클라이언트가 직접 수행한 일을 자동으로 엿보지 않는다. `configured`는 실제 프로세스가 살아 있다는 뜻이 아니고, 검증 근거가 없는 정보는 `unobserved`로 남긴다. 저장하지 않은 모델의 내부 추론도 표시하지 않는다.

새 화면은 `work/board`의 최대 60개 요약을 한 공유 SSE로 갱신하고, 선택한 Work만 `work/detail`로 읽는다. Work 레코드마다 브라우저·VM·타이머를 만들지 않는다. `work/start`는 모델 호출 전 먼저 원문과 ID를 저장한다. 현재 관제센터는 Work를 접수·정의하고, 연결된 에이전트가 Pack/Swarm/코딩 단계를 배정한다. 등록된 로컬 Git 프로젝트의 코딩 Run은 Work와 결속해 단계별 상태를 표시한다. 일반 CLI 작업의 Work 결속, 장기 외부 대기 재개, Work 전체 완료조건의 독립 검증은 아직 제공하지 않는다.

## 화면 미리보기 제거

작업자별 브라우저 Page는 실제 작업에 계속 사용하지만 주기적 스크린샷을 찍거나 관제 화면에 보내지 않는다. 상태 snapshot의 `frame_path`는 항상 `null`이며 기존 `surface/:id/frame` 주소는 404를 반환한다. 과거 설정의 `frame_interval_ms`와 `observability.surfaces`는 호환성을 위해 읽지만 미리보기 수집을 켜지 않는다. 이는 모델이 별도 작업에서 명시적으로 요청한 단일 증거 캡처까지 금지한다는 뜻은 아니다. 홈 화면의 이미지는 업무 결과로 저장된 이미지 파일을 Office가 직접 내려주는 것이며 브라우저 화면을 찍은 것이 아니다.

## 화면 구성

agent-driver run trace 스토리보드와 같은 디자인 언어를 쓴다. 어두운 바탕에 mono 중심 라벨을 쓰고, 판단 경로마다 색을 하나씩 둔다. Jev·진행 중은 앰버, LLM은 라일락, 코드는 파랑, 사람은 로즈, 검증 완료는 초록이다. 첫 화면은 **피드**다. 모든 산출물을 한 줄기로 최신순으로 보여 준다. 글 하나가 산출물 하나다: Office 업무가 저장한 회차별 결과(전달 문구, 결과 이미지, 전달된 곳), 서버 봇이 직접 보낸 글(아래 발송 기록), AI 앱이 `runtime_feed_post`로 올린 글, 연결한 AI 대화의 마지막 답변. 확인 필요 업무는 맨 위에 고정하고, 지난번에 피드를 떠난 뒤 새로 생긴 글은 **새**로 표시하며 사이드바 피드 옆에 수를 띄운다(이 기록은 그 브라우저에만 둔다). 날짜로 끊어 읽고, 전체·이미지·글·대화·확인 필요와 업무별로 거른다. 넓은 화면에서는 오른쪽에 지금 실행 중인 업무, 다음 산출물 예정, 서버 묶음 상태가 붙는다. 글의 **업무 열기**는 업무 상세로, **이 결과에 지시하기**는 그 업무의 대화 입력칸으로 바로 간다. 나중 회차가 같은 이름으로 바꿔 놓은 그림처럼 저장 당시와 달라진 파일은 보여 주지 않는다. `work/feed`는 저장된 기록만 읽고 모델을 부르지 않는다. 사이드바 맨 위 agent-office 로고와 **피드**는 어느 화면에서든 피드로 돌아온다. 업무 상세 위쪽의 **숨기기**는 업무를 화면에서만 뺀다(시연 영상처럼 개인적인 업무를 가릴 때). 숨긴 업무와 그 산출물은 피드·업무 보기·사이드바 숫자에서 빠지고 사이드바의 **숨김** 보기에만 나오며, 실행·예약·전달·서버 확인은 그대로 계속된다. **다시 보이기**로 되돌린다. 사이드바에는 업무 보기(피드·전체·확인 필요·실행 중·반복 실행·보류·종료된 업무·숨김), 가져오기, 사이트 로그인, 연결 및 설정, 그리고 에이전트 연결 상태(Codex·Claude Code·Hermes는 항상, 다른 앱은 연결됐을 때만. 초록 점 = Office MCP 연결됨, 앰버 = 설치됐지만 미연결, 회색 = 설치 안 됨. 연결 및 설정 화면과 같은 `settings/mcp` 확인을 쓴다)를 둔다. 반복 실행은 예약이 켜져 있고 지난 실행이 성공한 업무, 보류는 시작 전·일시정지·예약을 끈 업무다. 업무 보기는 보드(기본), 표 형식 목록, 타임라인으로 볼 수 있고 제목으로 검색된다. 타임라인은 최근 24시간을 업무마다 한 줄로 그린다. 실행 회차마다 막대 하나(성공 초록, 확인 필요 로즈, 진행 중 앰버, 중단 회색)이고, 지시 변경·재개·일시정지 같은 소유자 조작과 전달 실패는 점으로 표시한다. 도구·모델 이벤트는 하루 천 건을 넘을 수 있어 그리지 않는다. 카드는 이번 회차의 단계(접수 → 실행 → 완료 보고 → 확인 → 전달 → 다음 실행)를 점으로, 이번 회차에 일한 주체(코드·Jev·AI·사용자)를 태그로 보여 준다. 확인은 독립 검증이 돈 회차에만, 다음 실행은 반복 업무에만 나온다. 확인 필요 카드에는 멈춘 이유 한 줄이 붙는다. 업무가 하나라도 있으면 접수 폼은 **+ 새 업무**로 연다. 업무 상세는 run id·요청 줄·pack pill, 단계별 Run trace, 로즈 테두리의 Human control 패널로 구성된다. 업무 상세의 **산출물 기록**은 회차마다 한 줄(시각·결과 첫 줄·이미지와 파일 수·전달·상태)인 표다. 줄을 누르면 그 회차의 결과 글과 그림이 펼쳐지고, 파일 다운로드·출처·전달 기록(다시 시도 포함)은 그 안에 접혀 있다. 지금 나오는 산출물은 피드에서 본다. 내 AI 앱(Codex·Claude Code)이 실행하는 업무는 제목 아래에 세 칸 작업 공간이 먼저 나온다. **대화**는 처음 요청·내 지시·예약 실행·다시 시도와 회차마다의 클라이언트 답변을 시간순으로 보여 주고, 입력한 지시는 지시 저장과 이어가기를 한 번에 보내 같은 세션에 그대로 이어진다. **작업 리스트**는 답변 하나를 항목 하나로, 무엇이 시작시켰는지(처음 요청·지시·예약·다시 시도)와 답변 첫 줄·만든 파일·도구 사용 횟수를 최신순으로 보여 준다. 기본은 지시로 바뀐 회차만 보이고 **모든 회차**로 넓힌다. **로그**는 도구·모델 이벤트를 뺀 Office 기록이다. 항목을 누르면 대화가 그 답변으로 이동하고 로그는 그 회차 구간만 보여 준다. 세 칸은 `work/thread`가 이미 저장된 결과·지시·활동 기록으로 만들며 모델을 부르지 않는다. 긴 설명은 `?` 버튼의 모달로 연다. 외부 스크립트·폰트·이미지는 쓰지 않는다.

화면 언어는 영어가 기본이다. 우측 상단 국기 버튼으로 한국어로 바꾸며, 선택은 해당 브라우저의 localStorage(`office-lang`)에만 저장한다. 마크업의 원문은 한국어이고, 영어 모드에서는 `i18n.ts` 사전이 화면 문구·placeholder·aria-label을 렌더링 즉시 바꾼다. 사용자가 입력한 업무 제목·요청·모델 출력은 UI 문구와 정확히 같을 때만 바뀐다.

## 주소로 가져오기

**가져오기**는 **주소로 가져오기**로 열린다. 입력칸 하나에 로컬 폴더(`/home/...`, `C:\...`, `\\wsl.localhost\...`), 저장소(`https://github.com/...` 또는 `owner/repo`), 서버(`user@host`)를 넣는다.

- 폴더와 저장소는 주인의 기본 AI 앱(Codex 또는 Claude Code)이 자기 설정·도구 그대로, Office 데이터 폴더의 `import-analysis/<id>`에서 읽기 전용으로 분석한다(최대 20분). 저장소를 읽는 방법(gh, GitHub MCP, 복제)은 클라이언트가 고른다. Office는 파일 개수나 용량을 제한하지 않고, 원본을 바꾸거나 프로그램을 실행하지 말라는 지시와 결과 형식만 준다.
- 클라이언트는 `IMPORT.json`에 후보를 남긴다. 후보마다 **Office에서 실행**(기존 가져오기 초안 형식의 절차·완료·전달·근거 포함), **원래 자리에서 관측**(서버면 호스트와 SSH 사용자), **건너뜀** 중 하나다. Office는 후보마다 형식을 따로 검사해 초안이 빠졌거나 비밀값처럼 보이는 글이 있는 후보는 빼고 그 수를 알려 준다.
- 고른 **Office에서 실행** 후보는 다른 AI 답변을 붙여넣을 때와 같은 미리보기·수락 경로로 업무가 된다. 서버에서 관측할 후보와 서버 주소는 **서버 서비스** 화면으로 넘어가 접속 정보를 채운다.
- 프롬프트를 복사해 다른 AI 서비스에 붙여넣는 방식은 경로가 없는 자동화(다른 AI 서비스 안의 예약 작업 등)를 위해 맨 뒤 **다른 AI의 자동화**로 남는다.

## AI 대화 연결

**가져오기 → AI 대화 연결**은 데스크톱 앱이나 터미널에서 쓰던 Claude Code·Codex 대화(세션)를 업무로 붙인다. Office는 클라이언트 자신의 세션 파일(`~/.claude/projects/…/<id>.jsonl`, `~/.codex/sessions/…/rollout-….jsonl`)의 위치만 기록하고, 대화는 그 파일의 끝부분(최대 1MB)에서 읽는다. 사용자 문장과 답변, 도구 이름만 보여 주고, 시스템이 끼워 넣은 블록·하위 에이전트 기록은 빼며, 비밀값처럼 보이는 문자열은 가린다. Office 업무 폴더와 임시 폴더에서 돈 세션(Office 자신의 짧은 판단 호출 등)은 목록에 없다.

- 세션 파일이 90초 안에 바뀌었으면 **실행 중**(대화 진행 중), 아니면 **보류**(대화 대기)다.
- 상세 화면에서 보낸 지시는 세션이 1분 이상 조용할 때만 그 세션의 작업 폴더에서 같은 세션을 이어 실행한다(`claude -p --resume`, `codex exec resume`). 다른 곳에서 쓰는 중이면 거절한다. Claude가 이어 쓰며 새 세션 ID를 주면 업무가 그 ID를 따라간다.
- 데스크톱 앱에 같은 대화가 열려 있으면 앱 화면에는 바로 보이지 않을 수 있다.

## 서버 서비스 관측

**가져오기 → 서버 서비스**에서 내 리눅스 서버(SSH 키 접속과 호스트 키 등록이 된 서버)를 등록하고 **서비스 찾기**를 누르면, Office가 서버를 한 번 읽어 `/etc/systemd/system`에 있는 서비스·타이머와 Docker 컨테이너를 묶음으로 제안한다. 묶음은 이름 앞부분, `Wants`·`Requires`·`BindsTo` 의존, compose 프로젝트로 정한다. 묶음 이름을 고치고 서비스를 다른 묶음으로 옮기거나 빼서 **선택한 묶음 관측 시작**을 누르면 묶음마다 업무가 하나 생긴다. 이미 관측 중인 서비스는 다시 제안하지 않는다.

- 서버에서 실행하는 것은 고정된 읽기 전용 스크립트 하나다(`systemctl show`·`list-timers`·`list-unit-files`의 JSON 출력과 `docker ps`). 표준 입력으로 `sh -s`에 보내며 사용자나 서버의 문자열이 명령줄에 들어가지 않는다. SSH 옵션은 원격 OpenClaw 연결과 같다(BatchMode, StrictHostKeyChecking=yes, 포워딩 금지). systemd 246 이상이 필요하고, Docker는 SSH 사용자가 쓸 수 있을 때만 읽는다.
- 관측 중인 서버는 약 2분마다 읽는다. 정상인 묶음은 **반복 실행** 칸에 있고, 서비스 실패·멈춤, 타이머가 시작하는 작업의 마지막 실행 실패, 컨테이너 종료·unhealthy, 사라진 유닛이 있으면 **확인 필요**로 간다. 서버에 접속하지 못하면 "서버 연결 안 됨"이다. 일부러 끈(disabled) 타이머는 문제로 세지 않고 "꺼 둠"으로 보여 준다.
- 상태가 바뀐 순간만 업무 기록에 한 줄 남긴다. 상세 화면은 유닛마다 상태, 시작 또는 마지막 실행, 다음 실행, 재시작 횟수와 **지금 확인** 버튼을 보여 준다.
- **알림 받을 곳**: 서버 업무 상세에서 등록된 전달 대상(텔레그램 등)을 고르면, 상태가 바뀔 때(문제 발생·서버 연결 안 됨·회복) 짧은 알림을 한 번 보낸다. 결과 전달과 같은 업무별 전달 설정을 쓰고, 결과 머리말·꼬리말 없이 알림 문장만 보낸다.
- **활동 점검**: 프로세스는 살아 있는데 할 일을 하지 않는 경우(자기 안의 스케줄러로 발송하는 봇, 더 이상 돌지 않는 작업)를 잡는다. 업무마다 "이 유닛의 journal에 이 정규식과 맞는 줄이 이 기간 안에 있어야 한다"를 최대 10개 둔다. 유닛 이름과 문구는 base64로 스크립트에 실려 셸 변수로만 풀리고, 기간은 정수만 받는다. 맞는 줄이 0개면 **확인 필요**(최근 기록 없음)이고, 추가한 뒤 아직 읽지 않은 점검은 문제로 세지 않는다.
- Office는 서비스를 켜거나 끄거나 다시 시작하지 않는다.

## 발송 기록 → 피드

서버 봇이나 Hermes처럼 Office 밖에서 결과를 텔레그램 등으로 직접 보내는 것도 피드에 모은다.

- **서버 봇**: 서버 업무 상세의 **발송 기록 → 피드**에 봇이 보낸 기록을 연결한다. SQLite 파일과 조회문(`id`, `at`, `text` 열을 돌려주고 `title`은 선택)이나 한 줄에 하나씩 같은 키를 가진 JSONL 파일이다. Office는 2분마다 서버를 읽을 때 조회문과 경로를 base64 데이터로 보내 서버의 python3가 읽기 전용(`mode=ro`, `query_only`)으로 열고, 지난번 마지막 `at` 이후의 새 줄만 소스마다 최대 20개 가져온다. 처음 연결하면 최신 20개부터 시작한다. 같은 소스의 같은 `id`는 한 번만 글이 되고, 읽기 실패는 그 소스 줄에 표시한다. 조회문은 `SELECT`/`WITH`로 시작해야 하며, 쓰기는 서버 쪽 연결에서도 거부된다.
- **AI 앱**: Office MCP의 `runtime_feed_post` 도구로 같은 글을 피드에도 올린다(글만, 최대 2만 자). `external_id`를 주면 다시 불러도 한 번만 올라가고, `work_id`를 주면 그 업무의 글이 된다. 이 도구는 Office 밖으로 아무것도 보내지 않는다. 앱에게 "결과를 텔레그램으로 보낼 때 runtime_feed_post도 부르라"고 지침을 주면 된다.

## 휴대폰 푸시 알림

피드의 **알림 받기**는 그 기기의 브라우저 푸시를 켠다. 새 산출물이 피드에 들어오거나 업무가 새로 확인 필요가 되면 Office가 20초 안에 알린다(한 번에 넷 이상이면 한 통으로 묶는다). Office는 VAPID 키(데이터 폴더의 `push-vapid.json`, 소유자만 읽기)로 서명해 그 브라우저의 푸시 서비스(Apple·Google·Mozilla·Microsoft만)로 보내므로 휴대폰이 이 컴퓨터에 닿을 필요는 없고, 알림 내용(제목과 한 줄)은 그 구독용으로 암호화된다. 알림을 누르면 피드가 열린다. 푸시 서비스가 더는 모르는 기기는 자동으로 지운다.

아이폰은 iOS 16.4 이상에서 **홈 화면에 추가한 앱**에서만 켤 수 있다. Tailscale 주소(아래)로 Safari에서 열고 공유 → 홈 화면에 추가한 뒤, 그 아이콘으로 연 앱에서 **알림 받기**를 누른다. 앱은 접속 주소를 시작 주소로 기억해 스스로 로그인한다. PC가 켜져 있어야 알림이 나간다.

## 업무 내용의 AI 전송 동의

한 줄 업무 정의와 가져오기 분석은 `swarm`·`packs`·`coding`의 `model_data_approved` 중 하나, 또는 로컬 설정의 `work.model_data_approved`가 켜져 있어야 모델을 호출한다. 소유자가 관제센터 업무 보드에서 **업무 시작**을 누르면(접수 폼에 업무 내용이 선택한 AI로 간다고 적혀 있다) 그 자체가 동의이며, 처음 한 번 `~/.agent-driver/runtime-config.json`에 `{"work":{"model_data_approved":true,"approved_at":"…"}}`를 기록한다. 관제센터 AI 단계의 체크박스는 같은 값을 보여 주고 끄는(철회) 용도로 남는다. MCP로 들어온 등록·실행 요청은 이 기록이 없으면 그대로 멈춘다. 값은 호출마다 파일에서 다시 읽고 config fingerprint에는 포함하지 않는다. 동의가 없으면 업무는 `needs_model`, 사유 `MODEL_DATA_APPROVAL_REQUIRED`로 저장되고 상세 화면에서 허용 후 재시도할 수 있다. 호스트가 직접 관리하는 설정 파일은 이 화면에서 바꾸지 않는다.

## 로컬 제어와 안전

업무 단계 수정은 같은 출처의 사용자 조작과 revision을 확인하고, 이미 실행한 후속 단계를 조용히 다시 쓰지 않는다. 화면·상태 API는 capability URL로 보호하며 작업 실행·외부 제출 권한을 만들지 않는다. 사이트 로그인 정보와 비밀번호는 snapshot·활동 로그에 기록하지 않는다.

Ubuntu Browser VM의 새 기본 메모리 할당은 3GiB이며 필요하면 `vm launch --memory-mib`로 조절할 수 있다. 이 시험은 VM 부팅과 Chromium 제어 연결까지만 확인했다. 장시간 다중 탭 작업의 안정성이나 VM 자동 절전·재개는 아직 검증·구현하지 않았다.

## 다른 기기에서 열기 (Tailscale)

관제센터는 이 컴퓨터의 `127.0.0.1`에만 열린다. 휴대폰 같은 다른 기기에서 보려면 Tailscale을 쓴다. tailnet 안의 내 기기에서만 열리고, 접속 토큰은 그대로 열쇠로 남는다.

1. `runtime-config.json`의 `observability.tailnet_hosts`에 이 컴퓨터의 MagicDNS 이름을 브라우저가 보내는 그대로(포트 포함) 넣는다. 예: `"observability": {"tailnet_hosts": ["my-pc.tail1234.ts.net:4600"]}`. 다른 DNS 이름은 받지 않는다. 남이 그 이름을 이 컴퓨터로 가리키게 할 수 있기 때문이다.
2. Tailscale이 도는 쪽에서 HTTPS로 관제센터를 연다. WSL이면 Windows 쪽이다: `tailscale serve --bg --https=4600 http://127.0.0.1:4600`. Funnel은 인터넷 전체에 공개하므로 쓰지 않는다.
3. 관제센터를 다시 시작하면 `agent-office connect` 출력의 `tailnet_urls`에 휴대폰용 주소(`https://<이름>:4600/<토큰>/`)가 나온다. 처음 한 번 이 주소로 열면 토큰이 그 이름 전용 쿠키(HttpOnly·Secure)로 옮겨지고, 이후에는 `https://<이름>:4600/`만으로 열린다.

`tailscale serve`가 HTTPS를 끝내므로 그 페이지의 Origin은 `https://<이름>`이다. 관제센터는 허용한 이름에 한해서만 이것을 같은 페이지로 본다.
